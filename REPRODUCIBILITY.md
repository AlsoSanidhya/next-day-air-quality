# Reproducing this project

## Environment

Verified on Windows with Python 3.13.9, pandas 3.1.1, NumPy 2.5.5,
scikit-learn 1.9.1 and Matplotlib 3.11.2. Direct package versions are pinned in
requirements.txt. Tkinter is supplied by the Python installation.

From the repository root in VS Code PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe check_setup.py
.\.venv\Scripts\python.exe train_models.py
.\.venv\Scripts\python.exe make_report.py
.\.venv\Scripts\python.exe app.py
```

Commands use the explicit interpreter so activation is optional. Outside Windows,
use `.venv/bin/python` instead. Linux GUI use requires a display and tkinter.
Training and report generation use Matplotlib's noninteractive Agg backend.

## Data

The original 2,574,056-byte city_day.csv is included under data/raw/. For a manual
download, visit https://www.kaggle.com/datasets/rohanrao/air-quality-data-in-india,
download the dataset, extract city_day.csv and put it in that directory.
Use this same file to reproduce the reported numbers. No API key is required
to run the project once the CSV is present.

## Notebook order

Select the project environment as the notebook kernel, then execute:

1. notebooks/01-eda.ipynb
2. notebooks/02-preprocessing.ipynb
3. notebooks/03-models.ipynb
4. notebooks/04-evaluation.ipynb

Notebook 03 retrains all models using the same run_project function as the CLI.
Notebook 04 reads the generated files. All four notebooks were executed during
verification. A second independent training run reproduced all saved metrics
within numerical tolerance of 1e-10.

## Seeds and evaluation

RANDOM_SEED=42 is defined in src/data_preparation.py and passed to the stochastic
tree/forest estimators. The other models use deterministic settings. Forests
use n_jobs=1. Targets before 2020-01-01 are training data. The held-out target
dates are 2020-01-01 through 2020-07-01. Model selection is four expanding
TimeSeriesSplit folds with gap=1 within training data.

The split is on target dates, so a row with origin 2019-12-31 is in test data
because its target is 2020-01-01. Median imputation and StandardScaler are inside
the pipeline. Forward filling is limited to two consecutive missing days and
only uses earlier readings. Targets are never imputed.

All regression models and persistence share the same 183 test dates. Missing
origin PM2.5 is excluded from regression so persistence has an actual observed
input. Classification drops its own missing target rows and also has 183 test days.
Macro-F1 averages all six class labels. OvR AUC averages only defined class AUCs;
Good has no test positives and its AUC is explicitly recorded as undefined.

## Runtime and outputs

Training is small enough for a normal laptop CPU and needs no GPU. Allow roughly
1-5 minutes for training plus notebook startup, depending on CPU, disk and package
initialization. A fresh installation also needs internet access for package files.
The app predicts in well under a minute once the libraries are loaded.

Training recreates results/ and models/forecast_models.joblib. The report script
recreates report/report.pdf. On a fresh checkout, run training before the app.
Models are excluded from Git because they are generated environment-dependent
Python objects. Only load joblib artifacts generated by this project.

Minor floating-point differences may appear with different hardware, Python,
BLAS or package versions. GUI fonts and PDF metadata may differ. Compare numeric
metrics and predictions using tolerance, rather than binary file hashes.

## Verification performed

- Original CSV matched the archive entry byte for byte; all rows had 16 columns.
- Day shifts were checked manually against source readings.
- Changing future pollutant data left all earlier input features unchanged.
- Rolling features were unaffected by a change to origin-day PM2.5.
- Missing targets stayed missing, including the final next-day target.
- Saved imputer medians matched the training features' medians.
- Saved models reproduced the regression prediction CSV.
- The desktop window and prediction button worked, including a final-date forecast.
- Invalid negative, non-finite and excessively large custom readings were rejected.
- All notebooks ran, and repeated training reproduced the metrics.
- The four-page PDF was rendered and inspected.
